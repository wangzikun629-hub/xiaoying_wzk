# 真实模型验证记录

本文件记录真实接口接入与验证过程，最终汇总以03-evaluation.md为准。接口模型为用户配置的deepseek-flash；密钥仅保存在本地.env，未写入记录。

接入问题：首次沙箱请求发生连接错误；获准联网后服务返回404。进一步检查发现OPENAI_BASE_URL误填完整/chat/completions路径，SDK重复追加路径。按[DeepSeek官方接入说明](https://api-docs.deepseek.com/)修正为服务根地址，密钥和模型名不变，极小连通性请求成功。初始失败证据保留在examples/live-initial与examples/live-network-check。

首条真实预算路径：examples/live-pilot/C04-budget-replan中，模型先观察标准版12的报价，再选择精简版8，生成两份内容并正式保存。该Trace来自真实接口，不是Mock。

实际内容复查发现：精简版仍可能保留多个渠道，与本项目“精简版单渠道”的范围定义不一致。原费用表按交付物计价，因此当时数值计算未超预算，但业务范围约束不够完整。计划补齐单渠道检查、明确工具反馈，并重新运行；旧证据保留，不能只修改评估文案掩盖问题。

修复已实施：精简版多渠道报价scope_ok=false；预算替代项提供明确的可行渠道，但模型必须自己选择并重新估算；用户要求多渠道时不提供违反要求的精简报价。另检查BASE_URL不能包含完整/chat/completions。4项新增回归测试通过，当前完整测试45项通过。首轮真实全量17项通过，现进行范围修复后的复验与三轮独立重复评估。

运行期间不预填成功结果。每个运行的源码摘要、接口模型名、费用、工具观察与最终状态均保存在对应证据目录；最终完成结果见文末。

中间复验：live-validated共17项中16项通过，C09未完成原因错误。模型看到标准报价超预算且替代方案也超时，合理停止；宿主却返回current_plan_over_budget。原始失败见该目录C09输出，未发生生成或超支。修复后基于预算可负担候选的时间可行性判断停止原因，并分别返回最小时间缺口与当前方案时间缺口；直接回归测试验证33分钟与93分钟。

同时保存层检查排期、角色与核心信息中的已知渠道名，防止文字重新引入未选择渠道；错误反馈要求模型改写，成功脚本和费用保持不变。新增2项回归测试，完整测试47项通过。最终代码的全量运行保存在live-final，三轮重复在evaluation-final；中间版本12项关键重复评估均通过，仍保留在evaluation，不冒充最终代码结果。

此前单Agent最终结果：live-final全量17/17通过，evaluation-final四类场景各3次共12/12通过，mock-final17/17通过，自动测试47项通过。正常、预算调整、故障备用、部分成功、不可行、重复、上限、续跑均有实际输出与Trace。小样本不等于普遍可靠性，内容事实和运营适用性仍需审阅。当前子智能体版本结果及发布状态以03-evaluation.md和README为准。
