# 方案、动态决策与工程取舍

借鉴 Content Builder 的 `create_deep_agent`、业务记忆、Skills 和流式消息组织；本项目重新实现工具、状态、费用、恢复和证据。框架版本固定于 uv.lock：Deep Agents 0.7.32、LangChain 1.4.7、LangGraph 1.2.18。来源见 [upstream.md](upstream.md)。

调用链：CLI读取配置 → 校验输入/幂等 → SQLite加载成功结果 → Deep Agents模型选择动作 → AuditMiddleware记录并执行工具 → ToolMessage交回模型 → 模型继续或结束 → 宿主核对保存记录并导出。

四工具分别是检索、估算、生成、保存。工具调用不经过一个写死的串行调度器；模型可多次估算、改tier或backend、只补缺失项或停止。运行骨架由固定的合法交付物依赖构成：视频/图文依赖素材与可行报价，多渠道改写依赖基础内容，保存依赖当前选定的全部交付物。模型选择内容包和后端形成新计划版本，不能自由修改工具费用。

`tier=standard/economy` 控制内容范围，`backend=primary/backup` 控制生成方式。模型观察预算超限后选 economy、观察持续工具错误后选 backup，均通过下一次工具请求实现；Python代码只拒绝违反约束的请求，不代模型执行替代方案。

费用规则：视频4/35分钟，图文4/25分钟，改写4/60分钟；检索、估算、保存各1分钟且免费。估算不收费。已成功项的费用随结果一同提交；失败项0费用、1分钟，API token另计。报价绑定当前计划、素材、规则、成功结果；改变后需重新估算。保存不信任模型给出的金额。

economy限定单渠道，standard至少双渠道。替代项提供可行渠道建议，但模型必须自己选择并重新估算，不能删掉用户必需渠道。保存前核对排期、角色和核心信息中的已知渠道名，发现范围扩大则拒绝并要求修正文字，已有脚本不重复收费。该名称检查不承诺理解所有自然语言同义表达。

停止原因依据预算可负担候选的时间可行性判定，不能因为最后standard报价超预算，就忽略更便宜候选也来不及。最终输出区分最小时间缺口和最后报价时间缺口；不强制模型多做一次无意义估算来满足固定工具序列。

部分成功：视频成功4，图文失败0，工具返回 partial；保留视频ID与费用，模型只补图文4，总额8。失败尝试不覆盖。逻辑步骤恢复成功与旧尝试仍失败可以并存。

SQLite为事实来源，单个请求的运行由跨进程文件锁保护，工具执行由线程锁串行保护。LangGraph会在线程池执行工具，连接明确允许跨线程，但只在串行锁下修改；每个成功交付物结果和费用一次提交。正式方案和completed状态同一事务提交。模拟保存故障发生在事务前；另有实际存储函数异常测试。

业务状态支持进程重启后续跑，模型收到已成功结果及最新观察，重新决定动作。不宣称任意图节点精确检查点恢复或真实外部支付的恰好一次语义。未提交交付物的模型请求可能在进程中断后再次发生，API消耗可能增加，但已提交成功项不重复计业务费用。

Deep Agents使用 StateBackend 虚拟文件系统，只注入规则和Skill。中间件只向模型提供四业务工具、read_file及可用时的write_todos；调用层再次拒绝其他工具，包括task和execute。Agent接触不到宿主.env和SQLite。所有模型请求（包括生成内部请求）及工具调用都计数，默认20/32，模型客户端不自动重试。业务工具串行执行，即使模型一次提出多调用也逐个校验。

真实模式使用OpenAI兼容Chat Completions；配置来自.env。脚本主后端调用模型，备用后端为明确标记的本地模板；内容引用ID和结构由代码检查，语义事实与运营可用性需人工审阅。mock使用同一Deep Agents图和工具，但决策模型是确定性Python策略，生成使用模板，不证明真实推理。

模拟时钟：固定起始时间+累计工具耗时。真实时钟：当前墙钟+累计模拟工作耗时；后者未实际sleep，含API等待与停机墙钟流逝。保存、生成前均重新检查，续跑保留原时钟。选定方案生成前检查全部剩余内容与保存耗时，避免只做第一步就耗尽预算/时间。

Trace记录公开动作依据、工具参数/观察、费用与时间、调用ID及后续模型动作；不记录隐藏推理和凭据。最终状态只由工具实际记录导出；模型自然语言“完成”不能代替save_plan成功。
