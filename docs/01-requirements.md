# 需求与验收标准

用户为内容运营人员。目标是在主题不变、预算与截止时间满足的前提下，得到完整且已保存的活动方案；不可行时清楚说明缺口，保留已成功结果。

输入：主题、预算、截止时间；可选方案偏好、是否允许精简、必需渠道、请求 ID。素材与费用时间表分别是 [materials.json](../data/materials.json) 和 [cost_rules.json](../data/cost_rules.json)。费用为整数模拟单位。

输出：结构化任务计划、逻辑步骤状态、每次工具尝试、成功工具结果、费用合计、时间和正式保存位置或未完成原因。SQLite 保存正式方案 JSON，Markdown 为导出。

| 官方要求 | 本项目验收 |
| --- | --- |
| 正常完成 | C01：标准版费用 12，正式保存；依赖全满足 |
| 缺预算或截止时间 | C02a/b：needs_input，零模型及工具调用 |
| 工具失败 | C03a：注入一次图文失败，保留视频；C03b：主后端不可用，模型选择备用 |
| 预算超限 | C04：工具返回12后改选8；C05：预算5、最低8，返回缺口3且不生成 |
| 重复执行 | C06：相同输入返回同一方案，无重复费用与调用 |
| 部分成功结果驱动调整 | C07a/b：部分素材后降级或部分脚本后只补缺失项 |
| 明确停止与执行上限 | C08：达到上限返回 incomplete，成功结果仍在 |
| 截止时间与约束 | C09：时间不足；C10：相同ID不同输入冲突；C11：保存失败不是成功 |
| 失败步骤续跑（加分） | C12a/b：重启后复用视频或全部脚本，再完成剩余工作 |

真正的动态决策由模型在看到工具结果后选择动作。固定流程骨架、依赖检查、预算拒绝和调用上限由代码负责；自动重试不作为重规划证据。至少两条真实模型路径、三个以上实际样例和所有规定材料均是最终交付要求。

样例业务最低内容包为视频脚本与图文文案，合计8；标准版增加多渠道改写，合计12。精简不能删除最低交付，也不能删除用户必需渠道。此内容包为本项目自定范围，题面没有强制具体形式。

Deep Agents、CLI、SQLite、内容生成模型、20/32调用上限和重复评估次数是实现选择。界面、多 Agent、部署、发布与支付不在范围；开发工期不限，实际用时照实记录。

当前工程样例使用 mock；真实模型与个人贡献材料的完成情况以 [03-evaluation.md](03-evaluation.md) 和 [04-ai-usage.md](04-ai-usage.md) 为准。
