## 模型如何调整动作

[动作记录](../examples/final-decision-paths.md)列出工具参数、返回摘要、下一步及简要依据。重点看三条路径：C04 观察到标准版超预算后重新估算精简版；C03a 保留已生成视频，只补失败的图文；C03b 在主后端持续失败后重新估算备用方案。备用后端使用模板，结果中保留这一标记。

## 检查发现的问题

跨计划测试补查了渠道变化、素材版本、历史内容依赖和累计费用。结果复用现在要求范围与引用仍然有效，不能因为同名交付物已经存在就直接保存；改写会收到选定基础内容的正文和结果 ID。保存后停止模型请求，最终输出读取实际保存的方案。Markdown 导出失败会单独报告，保留已完成的数据库提交。

验收脚本还修正了失败场景的误报：无素材必须实际检索并得到 no_materials，保存失败必须实际调用保存并得到 save_failed。模型不可用不能算作业务场景通过。相关回归见[验收检查测试](../tests/test_evidence_checks.py)和[跨计划测试](../tests/test_replanning.py)。

[初轮真实运行](../examples/final-live-initial/summary.json)为18/19。C14 在旧报价下生成失败，模型重新估算备用报价后达到调用上限，当前报价尚未执行。新版按报价版本显示 pending，旧断言却要求 failed。修正后的检查同时核对当前报价尝试和历史故障，新增四项回归覆盖重新报价及未执行项被误标失败；随后完整重跑19个场景。初轮输入、输出、断言与Trace保留，归档绝对路径为运行时原始位置，应读取相邻文件。

旧版运行和失败过程见[历史评估](history-evaluation.md)。历史结果保留原源码摘要；当前审计只要求 final-mock、final-live 的全部元数据与当前源码一致。

## 限制和未完成部分

素材、费用及工具耗时为合成规则，本次没有执行真实发布或支付。正文只做结构和素材引用检查，事实准确性、表达质量及运营可用性仍需人工审阅。Mock 和本地 HTTP 协议测试不证明真实模型的决策效果。

续跑复用的是已提交业务结果，不是任意图节点的精确恢复。中断前未提交的模型请求可能再次发生，真实 API token 消耗不在模拟费用内。界面、部署和生产级运行环境未实现。
